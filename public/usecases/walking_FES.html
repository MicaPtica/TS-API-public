Walking FES

Quick access

What is Walking FES?

Walking FES (Functional Electrical Stimulation) is a use case demonstrating the application of the Teslasuit as a finite-state FES device. The project integrates Teslasuit’s motion capture and haptic systems to deliver targeted muscle stimulation during different phases of the gait cycle. This enables research and development in rehabilitation, assistive technology, and biomechanics.

The Walking FES system uses a motion capture interface with an applied data processing solution called the Step Detector. The Step Detector is an SLTM neural network model trained on pre-gathered IMU data (accelerometer and gyroscope) from both legs and the back of six healthy subjects during walking. The model achieved over 90% accuracy on the validation dataset, making it highly reliable for detecting gait phases.

The Step Detector provides time-series data about foot-floor contact for each foot separately. This data is sufficient to detect four simplified walking phases:

  1. Initial Stance
  2. Terminal Stance
  3. Initial Swing
  4. Terminal Swing

Simplified electrical stimulation patterns are assigned to these phases to assist walking. The system operates as an open-loop finite-state machine, where stimulation patterns are triggered based on detected gait phases without real-time feedback adjustment.

How It Works

The Walking FES system uses the following workflow: 1. Predefined Haptic Assets:
Predefined haptic patterns are loaded from external assets (e.g., JSON files). These patterns define stimulation parameters such as amplitude, duration, and pulse width for each muscle group. 2. Step Detection:
The Step Detector processes IMU data to detect foot-floor contact and classify the current gait phase. 3. Haptic Animation Playback:
Based on the detected gait phase, the system plays the corresponding haptic animation for the muscle group responsible for that phase. This is done in an open-loop manner, where the operator can regulate the duration and delay of the haptic animation through the GUI interface.

Motion Capture Example

from suit_handler import Teslasuit
from mocap_processor import MocapStreamer

# Initialize Teslasuit and connect
suit = Teslasuit()
suit.connect_suit()

# Start mocap streaming
streamer = MocapStreamer(suit)
streamer.update()

# Example: Retrieve quaternion data for a specific node
q6_data = streamer.get_q6(index=1)  # Replace '1' with the desired node index
print("Quaternion data:", q6_data)

# Example: Process gait features
streamer.get_features()
gait_phase = streamer.run_model()
print("Detected gait phase:", gait_phase)

Explanation:
The MocapStreamer class processes raw mocap data from the Teslasuit to extract features such as accelerometer and gyroscope readings. These features are fed into the Step Detector model to classify the current gait phase. The detected gait phase is then used to trigger predefined stimulation patterns.

Key functions in mocap_processor.py: - update(): Updates the mocap data buffer for all nodes. - get_q6(index): Retrieves quaternion data for a specific node. - get_features(): Extracts normalized features (e.g., accelerometer and gyroscope magnitudes) for gait phase detection. - run_model(): Runs the Step Detector model to classify the current gait phase.

Haptic Feedback / FES Example

from fes import Fes_streamer

# Initialize FES streamer with preloaded assets and suit haptic player
fes = Fes_streamer(assets=suit.asset_id_list, haptic=suit.haptic)

# Enable muscles (operator toggles)
fes.ChangeHapticChecked('left', 'Left_quadriceps', 1)
fes.ChangeHapticChecked('left', 'Left_tibialis', 1)

# Trigger a Left Swing pattern (quad/tib/ham if enabled)
fes.play_L_Sw()

# Each frame or timer tick: update which assets should play and push to device
fes._update_playing_assets()
fes._update_playing(suit.haptic)

Explanation:
The Fes_streamer manages prebuilt haptic animations (assets) per muscle, provided as a mapping asset_id_list at startup. Operator controls enable/disable specific muscles via ChangeHapticChecked. Phase helpers like play_L_Sw, play_L_St, play_R_Sw, play_R_St start timers. _update_playing_assets() applies per-muscle delay/length windows, and _update_playing(haptic) calls haptic.play_playable(asset_id) for active muscles.

Default per-muscle timing (seconds): delays - gastrocnemius 0.1, hamstring 0.4, quadriceps 0.1, tibialis 0.0; lengths - gastrocnemius 0.3, hamstring 0.2, quadriceps 0.4, tibialis 1.0 (left/right symmetric).

Open-loop Finite-State Control Example

# Detector result per frame:
# result[1] -> Left foot contact (0: Swing, 1: Stance)
# result[3] -> Right foot contact (0: Swing, 1: Stance)

# Map detector output to muscle patterns and schedule playback
fes.run_walking_fes(result)

# Apply timing windows and play active assets
fes._update_playing_assets()
fes._update_playing(suit.haptic)

Explanation:
The controller is an event-driven open-loop finite-state machine. For each frame, the Step Detector provides contact states; run_walking_fes(result) maps states to muscle groups and sets timers: - Swing: quadriceps, tibialis, hamstring on the swinging leg - Stance: gastrocnemius on the stance leg

Operator controls gate which assets are eligible. Playback timing is governed by per-muscle delay and length; the system does not adapt stimulation based on real-time feedback.

Key Components

  • Motion Capture Sensors:
    Used to detect gait phases in real time, providing input for the finite-state control system.

  • Haptic Channels:
    Specific electrode channels are activated to stimulate the muscles responsible for walking, such as the quadriceps, hamstrings, gastrocnemius, and tibialis anterior.

  • Finite-State Control System:
    The project includes an open-loop finite-state control system that processes mocap data and applies stimulation based on predefined patterns.

  • Step Detector Model:
    A neural network trained on IMU data to classify gait phases with over 90% accuracy.

  • GUI Interface:
    The application provides a graphical interface for controlling stimulation parameters such as duration and delay for each muscle group.

Example Workflow

  1. Setup:
    Connect the Teslasuit and ensure all sensors and electrodes are properly positioned.
  2. Calibration:
    Calibrate the motion capture system and EMS stimulation parameters.
  3. Stimulation:
    Use the application to deliver FES to the appropriate muscle groups, adjusting parameters as needed.
  4. Monitoring:
    Observe real-time feedback on gait phases and muscle stimulation, making adjustments to optimize performance.
  5. Data Collection:
    Collect data on gait phases, stimulation parameters, and muscle responses for analysis.
  6. Analysis and Iteration:
    Analyze the collected data to refine stimulation strategies. Iterate on the design and implementation based on experimental findings.

Note: This use case demonstrates how Teslasuit’s integrated systems can be used for advanced rehabilitation and research scenarios. The system operates as an open-loop finite-state machine, meaning it does not dynamically adjust stimulation based on real-time feedback but instead relies on predefined stimulation patterns triggered by detected gait phases.

Warning

⚠️ Safety: Before using electrical stimulation, make sure the haptic system is calibrated and working. Start with conservative stimulation settings: low amplitude and short duration.
